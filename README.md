# Хронометраж — система хронометража велокросса

Flask-приложение для проведения соревнований по велокроссу: регистрация участников,
старты, ручной и RFID-хронометраж, итоговые протоколы и публичное табло.

Работает локально (Windows/Linux) и в Docker; на одном сервере можно вести несколько
соревнований — у каждого своя база и свой адрес.

## Возможности

- **Участники и категории** — ручное добавление, импорт из Excel, печать номеров,
  RFID-метки, автоматический подбор категории по полу и году рождения.
- **Самостоятельная регистрация** — участник заполняет форму с телефона, заявка попадает
  в журнал регистрации с технической информацией (IP, браузер, ОС, устройство).
- **Старты** — групповой старт (круги, отставание, «финиш после лидера») и **раздельный
  старт (ITT)**: стартовое табло с обратным отсчётом, очередь с ручной перестановкой,
  порядок «по номеру» или «по группе, затем номер».
- **Хронометраж** — ручной ввод номера (КРУГ/ФИНИШ), учёт отметок с RFID-считывателя,
  защита от двойных срабатываний, живое время на дистанции.
- **Результаты и протоколы** — места, отставание, средняя скорость; протокол по образцу
  официального документа с экспортом в PDF и Excel.
- **Публичное табло** — экран финиша для проектора/телевизора с QR-кодом на сайт.
- **Управление** — несколько соревнований, архив, права только на чтение, журнал
  технических действий (кто и когда вносил отметки).

## Быстрый старт

Нужен Python 3.11+.

```bash
python -m venv .venv
.venv\Scripts\activate        # Windows
# source .venv/bin/activate   # Linux / macOS

pip install -r requirements.txt
python app.py
```

Приложение поднимется на <http://127.0.0.1:5000> (HTTPS — на 5001, если есть сертификаты).
При первом запуске создаётся администратор `admin` / `admin` и база `chrono.db`.

> Локально удобнее `start.bat` — он создаёт окружение, ставит зависимости и запускает сервер.

## Docker

```bash
cp docker-compose.hrono.example.yml docker-compose.yml
# задайте CHRONO_SECRET_KEY и пароль администратора
docker compose up -d --build
```

| Переменная | Назначение | По умолчанию |
|---|---|---|
| `CHRONO_SECRET_KEY` | ключ подписи сессий (**обязательно свой**) | генерируется временный |
| `CHRONO_DB` | путь к базе основного соревнования | `chrono.db` |
| `CHRONO_USER` / `CHRONO_PASS` | логин и пароль администратора | `admin` / `admin` |
| `CHRONO_PUBLIC_URL` | публичный адрес для QR-кодов | — |
| `CHRONO_HTTP_PORT` / `CHRONO_HTTPS_PORT` | порты | `5000` / `5001` |
| `CHRONO_HTTPS` | `0` — за обратным прокси с TLS | `1` |
| `CHRONO_PROXY` | доверять заголовкам `X-Forwarded-*` | `0` |
| `CHRONO_LOG_DIR`, `CHRONO_CERT_DIR` | каталоги логов и сертификатов | рядом с базой |

Данные (базы, логи, сертификаты) хранятся в томе `/data`.

## Несколько соревнований

Реестр соревнований — `competitions.json`, у каждого своя база:

```
chrono.db                  # основное (можно удалить — создастся заново)
comps/<slug>.db            # остальные соревнования
competitions.json          # реестр: slug, название, путь к базе, флаги
```

Соревнования создаются и архивируются на странице «Управление соревнованиями» (`/manage`).

## Обновление и схема базы

Схема базы всегда соответствует текущей версии кода — приложение создаёт недостающие таблицы
и настройки по умолчанию. **Автоматических миграций из старых версий нет**: перед обновлением
сделайте копию каталога с данными (`/data`), а если структура изменилась несовместимо —
перенесите данные вручную или создайте соревнование заново.

```
requirements.txt        # локальный запуск
requirements-docker.txt # образ без USB-зависимостей (RFID-считыватель на хосте)
```
