# Объединение категорий — вариант логики (не реализовано)

Решения зафиксированы по ответам пользователя:
1. Участники переезжают **в одну из существующих** категорий (новых не создаём).
2. Условия (пол/возраст) объединённой категории — **объединение диапазонов**.
3. Удаляются все выбранные, кроме целевой; **у целевой не меняются** название,
   круги и порядок.
4. Объединять **разный пол разрешено** (М + Ж → оба пола).
5. Категории, участвовавшие в проведённых стартах, **объединять запрещено**.
6. `sort_order` — **как у целевой**.
7. Точка входа — **в таблице категорий**.
8. Порог «мало участников» — **меньше 3** (окончательно).

---

## 1. Интерфейс

В таблице категорий (`/competitions/<cid>/categories`):

- слева новая колонка с чекбоксом выбора (как у участников);
- в шапке над таблицей — «Выбрать все» и кнопка **«Объединить (N)»**,
  активна при выборе ≥ 2 категорий;
- клик по кнопке открывает диалог **«Объединить категории»**:
  - список выбранных: название, пол, возраст, число участников;
  - выбор целевой категории (radio, по умолчанию — первая выбранная с наибольшим
    числом участников);
  - предупреждение: «Категории-источники будут удалены: …»;
  - пояснение: «Круги и порядок целевой категории не меняются; условия
    (пол/возраст) расширятся до объединённых»;
  - кнопки «Объединить» / «Отмена».
- после успеха — перезагрузка страницы и flash:
  «Объединено: N категорий → «Целевая»; участников переехало: M; условия: Ж, 10–17 лет».

Счётчики участников и подсветка пустых/малых категорий (уже есть) после
объединения пересчитываются автоматически.

## 2. Серверный маршрут

`POST /competitions/<int:cid>/categories/merge` → `categories_merge`,
поля формы: `target_id`, `ids` (несколько значений).

Возврат: redirect на список категорий с flash (или JSON при
`X-Requested-With: fetch` — `{ok, merged, moved, target, gender, age_range}`).

### Проверки (порядок важен)

1. `ids` — целые, уникальные, ≥ 2; все принадлежат `cid`.
2. `target_id` входит в `ids`.
3. Целевая категория существует.
4. **Запрет по проведённым стартам** для категорий-источников:
   ```sql
   -- категория привязана к старту, который уже идёт/завершён или имеет результаты
   SELECT DISTINCT hc.category_id
   FROM heat_categories hc
   JOIN heats h ON h.id = hc.heat_id
   LEFT JOIN races r ON r.heat_id = h.id
   WHERE hc.category_id IN (...) AND (h.status IN ('running','finished') OR r.id IS NOT NULL)
   ```
   Если такие есть — ошибка: «Нельзя объединять категории, участвовавшие в стартах:
   «…», «…». Сначала удалите или завершите эти старты.»
   (Целевая категория может быть использована — её результаты не меняются.)

## 3. Объединение условий

### Пол
Берём допустимые полы каждой категории (`_cat_genders`: пусто = оба).
Итог — объединение множеств: `{M}` + `{F}` → `MF`; если хотя бы одна категория
без ограничения — результат `MF` (оба пола).

### Возраст
Каждый `age_range` разбирается `_parse_age_range` → `(age_min, age_max)`.
- если хотя бы одна категория без возрастного ограничения — итог без ограничения;
- иначе `min(age_min)` и `max(age_max)`, где `None` означает «без границы»
  (`-8` → min нет; `18-` → max нет);
- строка собирается `_format_age_range`, годы — `_age_range_years(start_year, …)`
  (возраст на 31 декабря года старта, как везде).

Примеры:
| Было | Стало |
|---|---|
| `12-14` + `15-17` | `12-17` |
| `-8` + `9-10` | `-10` |
| `18-` + `40-` | `18-` |
| `12-14` + пусто | без ограничения |

### Круги и порядок
Не меняются — остаются у целевой категории (согласно решениям 3 и 6).

### Название
Не меняется (у целевой). При желании пользователь переименует вручную —
имя редактируется в той же таблице.

## 4. Транзакция (один `BEGIN`/`COMMIT`)

```sql
-- 1) участники источников → в целевую
UPDATE participants SET category_id = :target WHERE competition_id = :cid
  AND category_id IN (:sources);

-- 2) привязки незапущенных стартов → на целевую (чтобы старт не осиротел)
INSERT OR IGNORE INTO heat_categories (heat_id, category_id)
  SELECT heat_id, :target FROM heat_categories WHERE category_id IN (:sources);
DELETE FROM heat_categories WHERE category_id IN (:sources);

-- 3) условия целевой
UPDATE categories SET gender = :gender, age_range = :age_range,
  year_from = :year_from, year_to = :year_to WHERE id = :target;

-- 4) удалить источники
DELETE FROM categories WHERE competition_id = :cid AND id IN (:sources);
```

Порядок 2→4 важен из-за `FOREIGN KEY` на `heat_categories`.
Всё в одной транзакции: при ошибке ничего не меняется.

## 5. Что считается «переездом» и как считаются числа

- `moved` — `SELECT COUNT(*)` участников с `category_id IN (sources)` до `UPDATE`.
- `merged` — число удаляемых категорий (`len(sources)`).
- После операции пересчитывать ничего не нужно: результаты хранят
  `participant_id`/`heat_id`, а не категорию; протоколы и итоги берут категорию
  из участника.

## 6. Ошибки и предупреждения

- «Выберите хотя бы две категории» / «Выберите категорию, в которую объединять».
- «Нельзя объединять категории, участвовавшие в стартах: …».
- После объединения — предупреждение, если новые условия пересекаются с
  другими категориями (`_category_overlaps` уже умеет это находить):
  «Внимание: условия «Ж, 10–17» пересекаются с «Ж, 15–17»».

## 7. Тесты (pytest)

1. Две категории одного пола: участники переехали, источники удалены,
   название/круги/`sort_order` целевой не изменились.
2. Объединение М + Ж: итог `MF`, участники обоих полов в целевой.
3. Возраст: `12-14` + `15-17` → `12-17`; `-8` + `9-10` → `-10`;
   `18-` + `40-` → `18-`; с пустым возрастом → без ограничения.
4. Запрет при категории в завершённом старте (flash/JSON-ошибка, данные не изменились).
5. Разрешено, если категория только в `pending`-старте: привязка
   `heat_categories` переехала на целевую.
6. Меньше двух выбранных / целевая вне списка → ошибка.
7. Счётчики на странице категорий после объединения соответствуют новым данным.
