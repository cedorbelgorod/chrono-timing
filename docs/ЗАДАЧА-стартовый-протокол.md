# Задача: порядок участников в разделке и стартовый протокол

Статус: **реализовано** (23.11.2026), проверено локально и на hrono.cedor.ru.

## 1. Цель

Дать судье управлять стартовым порядком разделки до запуска старта и получить
**стартовый протокол** — документ «кто и когда стартует», доступный и внутри системы,
и по публичной ссылке для участников.

## 2. Принятые решения

| Вопрос | Решение |
|---|---|
| Где перетаскивать | только страница **«Старты»**, карточка старта (на табло остаются стрелки ↑/↓ как есть) |
| Плановое время старта | **добавляем**: поле у старта, задаётся при создании и правится в карточке |
| Виды протокола | **предстартовый** + **текущий** (фактические времена во время гонки) |
| Публичный доступ | **публичная ссылка** на стартовый протокол без входа |
| Перестановка после запуска | **разрешена** для тех, кто ещё не стартовал |

## 3. Модель данных

1. `heats.start_at` (TEXT, ISO `YYYY-MM-DDTHH:MM`) — плановое время первого участника.
   Пусто — время не задано (в протоколе «—», старт по факту).
2. `heats.startlist_token` (TEXT) — короткий случайный токен для публичной ссылки,
   создаётся при первом запросе ссылки. Пусто — ссылки ещё нет.
3. `heat_participants.sort_order` — **уже существует**, используется для ручного порядка.
4. `heats.start_order` — прежний режим автосортировки (`number` / `category`).
   Ручной порядок перебивает автосортировку; сброс автоочищает `sort_order`.

Схема БД обновляется одноразово на сервере (в проекте нет автмиграций): добавить две
колонки в таблицу `heats` во всех базах `/data/*.db` и `/data/comps/*.db`.

## 4. Серверные маршруты

| Маршрут | Назначение |
|---|---|
| `POST /heats/<hid>/order` | сохранить порядок ожидающих участников (список id в визуальном порядке) |
| `POST /heats/<hid>/reset_order` | сброс порядка: `mode=number` или `mode=category` |
| `POST /heats/<hid>/start_at` | сохранить/очистить плановое время старта |
| `POST /heats/<hid>/startlist_link` | создать (если нужно) и вернуть публичную ссылку |
| `GET /heats/<hid>/startlist` | предстартовый/текущий протокол (внутри, по логину) |
| `GET /heats/<hid>/startlist.pdf` | PDF-версия |
| `GET /heats/<hid>/startlist.xlsx` | Excel-версия |
| `GET /sl/<token>` | публичная страница протокола без логина |

Правила:

- `order` принимает только участников этого старта; участники, уже имеющие заезд
  (стартовавшие), в запрос не входят и не меняются.
- После сохранения порядок ожидающих перенумеровывается 1…N.
- `reset_order` очищает `sort_order` у всех участников старта.
- Для группового старта маршрут порядка отвечает ошибкой «только для раздельного старта».
- `start_at` проверяется на корректность формата; пустое значение допустимо (сброс).
- Публичная страница отдаёт только протокол выбранного старта, без служебных данных.

## 5. Экран «Старты» — карточка старта (разделка)

### До запуска (`pending`)

Список участников в порядке старта:

- колонки: **⋮⋮ (ручка)**, **№ позиции**, **номер**, **ФИО**, **группа**, **время старта**, **статус**;
- перетаскивание за ⋮⋮ (как в категориях), автосохранение сразу после переноса;
- индикатор «Порядок сохранён» / ошибка сохранения;
- кнопки **«↺ По номеру»** и **«↺ По группе»** — сброс к автосортировке;
- бейдж режима: «порядок ручной» / «по номеру» / «по группе»;
- поле **«Старт в»** (дата-время) с кнопкой сохранения; если не задано — подсказка;
- кнопки **«📋 Стартовый протокол»** и **«🔗 Публичная ссылка»** (копирование в буфер);
- плановое время в строке = `start_at + (позиция − 1) × интервал`; помечать «—», если не задано.

### Идёт (`running`)

Карточка делится на две части:

- **Стартовали** — без перетаскивания: номер, ФИО, фактическое время старта, статус
  (на дистанции / финиш + время / DNS);
- **Ожидают старта** — перетаскиваемые, плановое время.

### Финальный (`finished`)

Перетаскивание выключено, показываются результаты (как сейчас).

### Групповой старт

Перетаскивание и плановое время не показываются; протокол доступен, но без времени
(список участников по группам/номерам).

## 6. Стартовый протокол

Два режима одного документа:

1. **Предстартовый** — порядок + плановое время (или «—», если `start_at` не задано).
2. **Текущий** — у стартовавших фактическое время, у ожидающих плановое, у DNS — «DNS»;
   у едущих в примечании «на дистанции».

Состав:

- шапка: соревнование, дата, «Стартовый протокол. Старт №N», интервал старта,
  дистанция/круг, число участников;
- таблица: **№ п/п · номер · ФИО · год рождения · группа · город · команда ·
  время старта · примечание**;
- подвал: главный судья, секретарь (как в итоговом протоколе);
- веб-версия: страница с кнопками «Скачать PDF», «Скачать Excel», «Печать»;
- PDF: A4, повтор шапки на каждой странице, ширины колонок проверяются так же, как
  в итоговом протоколе (без разрывов слов);
- Excel: один лист, те же колонки.

## 7. Публичная ссылка

- Вид: `https://<домен>/sl/<token>`, токен — 8 символов, уникален в пределах базы.
- Без авторизации; в шапке — название соревнования, но без ссылок на разделы.
- Автообновление раз в 10–15 секунд (страница лёгкая, только таблица + время).
- Адаптивность: читается с телефона (участники открывают на старте).
- Кнопка «Обновить ссылку» — перегенерировать токен (старая ссылка перестаёт работать).

## 8. Тесты

Серверные:

- порядок: сохранение, перенумерация 1…N, чужие участники → ошибка, групповой старт → ошибка;
- после запуска: стартовавшие не входят в запрос, порядок ожидающих меняется;
- сброс порядка: по номеру и по группе, `sort_order` очищается;
- `start_at`: сохранение, сброс, некорректный формат;
- протокол: порядок строк, плановое время = start_at + шаг × позиция, фактические
  времена у стартовавших, DNS и «на дистанции»;
- публичная ссылка: 200 без логина, неизвестный токен → 404, смена токена;
- PDF и Excel: 200, непустые, колонки на месте.

Интерфейс (jsdom):

- drag & drop в карточке старта → уходит один запрос с новым порядком, индикатор «сохранён»;
- кнопки сброса меняют порядок и режим;
- после запуска перетаскиваются только строки «Ожидают старта»;
- правка «Старт в» сохраняется и пересчитывает время в строках.

Регресс: массовый старт, разделка на табло, результаты, итоговый протокол, категории.

## 10. Этапы

1. **Схема и API** — колонки `start_at`, `startlist_token`; маршруты порядка, сброса,
   планового времени, ссылки; одноразовое обновление баз.
2. **Карточка старта** — список с перетаскиванием, автосохранение, сброс, поле «Старт в»,
   разделение на «стартовали / ожидают» после запуска.
3. **Протокол** — сборка данных, HTML-страница, PDF, Excel.
4. **Публичная ссылка** — токен, публичный маршрут, автообновление, копирование.
5. **Тесты, документация, деплой, пуш.**

## 11. Открытые мелочи (уточним по ходу)

- формат ввода планового времени — дата-время (`datetime-local`), чтобы можно было
  ставить протокол на другой день;
- если `start_at` не задано — протокол показывает «—», а после запуска подставляет
  фактическое время первого стартовавшего;
- число строк на странице PDF — по факту, повтором шапки.
