# Задача: разделка с несколькими кругами (число кругов задаёт категория)

Статус: **реализовано** (23.11.2026), проверено локально и на hrono.cedor.ru.

## 1. Требования

- Разделка может проводиться на кольцевой трассе с **несколькими кругами**.
- **У каждой категории — своё число кругов** (`categories.laps_total`).
- Участник всегда проезжает ровно заданное число кругов; финиш — на последнем круге.
- Понятия «финиш после лидера» в разделке **нет** (уже отключено: `heat_create` ставит
  `finish_on_leader = 0` для `itt`).
- Обновить: **табло старта**, **хронометраж (круги)**, **результаты**, **протокол/PDF**,
  **экспорт Excel**, табло финиша и дашборд.

## 2. Сейчас (что мешает)

Заезды разделки создаются с `laps_total = planned_laps = 1` (хотя логика `manual_action`
уже умеет считать много кругов — она используется для массового старта). Поэтому
разделка фактически «однокруговая»:

- `_start_heat` (ветка `itt`): `laps = 1 if is_itt else p['laps_total']`;
- `manual_start_action` (действия `start` и `skip`): вставляют заезд с `..., 1, 1, ...`;
- хронометраж для разделки показывает «ФИНИШ (круг 1/1)».

## 3. Задачи по коду

### 3.1. Число кругов заезда разделки

1. `_start_heat`, ветка `itt`: вместо `laps = 1` брать круги категории участника
   (`p['laps_total']`, уже выбирается как `COALESCE(c.laps_total, 1)`).
2. `manual_start_action`:
   - действие `start` — создавать заезд с `laps_total = planned_laps = круги категории`;
   - действие `skip` (DNS) — то же самое (чтобы статистика/протокол показывали N кругов).
3. `_manual_start_queue`: вернуть `laps_total` (и `category_name` уже есть) — понадобится
   табло и созданию заезда.
4. Участник без категории — 1 круг (как сейчас по умолчанию).

### 3.2. Хронометраж

5. `_get_manual_data` / partial `_manual_active.html`: для разделки вместо
   «ФИНИШ (круг 1/1)» показывать «Круг X/N · в пути: мм:сс».
6. `manual_action` — логика кругов уже общая (`laps_done < laps_total` → круг, на последнем
   финиш): проверить, что после п. 3.1 для разделки всё сходится; финиш = последний круг.
7. RFID/авто (`_process_tag_scan` и связанный код): каждая метка — круг, на N-й — финиш.
   Проверить, что для разделки нигде не зашито «1 круг».
8. `maybe_finish_heat`: старт завершается, когда все стартовавшие финишировали
   (после своих N кругов); DNS не мешают.

### 3.3. Табло старта

9. `manual_start.html` + `/manual/start/data`: у «Стартует №…» (и, по желанию, в очереди)
   показывать **«Круги: N»** по категории следующего участника.

### 3.4. Результаты

10. `_build_results_detail` (ветка `itt`): добавить колонку **«Круги»** (`X / N`).
11. **«Место (сейчас)»** — живое промежуточное место (фишка, см. п. 3.6).
12. `results_export` (xlsx, ветка `itt`): добавить колонку «Круги».
13. Табло финиша (`_build_heat_view` / `finish_screen`): уже показывает «Круги X/N» —
    проверить для разделки после п. 3.1; при желании — то же «Место (сейчас)».

### 3.5. Протокол и стартовый протокол (PDF)

14. `_build_protocol` / итоговый PDF (ветка `itt`): добавить колонку **«Круги»** (число
    кругов категории участника, `N`); время и места — как сейчас.
15. Стартовый протокол (`_heat_start_rows` / `_heat_startlist_data` / `_startlist_table.html`
    / PDF / Excel): добавить колонку **«Круги»** (плановое `N` по категории) — в том числе
    в публичную версию.

### 3.6. Живое «Место (сейчас)» — как считать

Текущее (промежуточное) место в реальном времени, по возрастанию времени, **внутри своей категории**:

- **финишировавшие** — итоговое время (финиш − старт);
- **едущие** — текущее «в пути» = сейчас − старт (обновляется при каждом обновлении страницы);
- **DNS / не стартовавшие** — без места («—»);
- при равенстве — по номеру, для стабильности.

Категории между собой **не смешиваются**: у каждой категории свой зачёт мест (как сейчас).
Показывается в результатах (и, опционально, на табло финиша) колонкой **«Место (сейчас)»**;
итоговое «Место» остаётся отдельной колонкой и заполняется по факту финиша.

### 3.7. Данные и совместимость

16. **Новые** старты разделки используют круги категории. Уже созданные старты
    (с `laps_total = 1`) остаются как есть — при необходимости пересоздать старт.
17. `min_lap_time` уже действует на каждый круг — для разделки работает без изменений.

## 4. Тесты

- Категории с разным `laps_total`; ITT-старт; СТАРТ участника → `laps_total`/`planned_laps`
  равны кругам его категории.
- Кнопка КРУГ N−1 раз → статус `running`, «Круг X/N»; на N-м нажатии → финиш и время.
- `min_lap_time`: быстрый круг отменяется.
- RFID: N меток → финиш; меньше N — «на дистанции».
- Старт завершается после финиша всех; DNS не блокируют.
- Табло: «Круги: N» у следующего.
- Результаты: колонки «Круги» и «Место (сейчас)»; «Место (сейчас)» корректно ранжирует
  финишировавших по итоговому времени и едущих по «в пути», обновляется с автообновлением.
- Стартовый протокол (веб/PDF/Excel) и итоговый PDF: колонка «Круги».
- Регресс: массовый старт, прежние разделки (1 круг), отмена старта/пропуск, категории.

## 6. Решения (согласованы 23.11.2026)

1. **Круги в результатах** — да, отдельная колонка.
2. **Живое место** — да: колонка «Место (сейчас)», как в п. 3.6.
3. **Число кругов в PDF** — да: и в итоговом протоколе, и в стартовом протоколе.
4. **Смешанные категории** — места по общему времени **внутри каждой категории**
   (у каждой категории свой зачёт 1-2-3), категории между собой не смешиваются — как сейчас.
