# Задача: YanPoDo + MQTT — подробный план интеграции

Статус: **постановка** (код не менялся). Составлено 23.11.2026.

## 1. Зачем и как это работает

Сейчас считыватель YanPoDo подключён по USB-serial к тому компьютеру, где работает
приложение (`_swrfid_listener` в `chrono/rfid.py`). Если финиш далеко от сервера,
тянуть USB-кабель неудобно, а Raspberry Pi/ноутбук у трассы не может отдавать данные.

Схема с MQTT развязывает это:

```
[YanPoDo RU5300/5500] --USB--> [ноутбук/RPi у финиша]
                                  │  swrfid-mqtt (или swrfid + свой мост)
                                  │  публикует JSON в MQTT
                                  ▼
                        [MQTT-брокер: mosquitto]
                                  │  на сервере / в Docker
                                  ▼
                        [chrono-site: подписчик paho-mqtt]
                                  │  → _process_tag_scan() → круги/финиш
                                  ▼
                        БД соревнования, табло, журнал
```

Плюсы: не нужен кабель до сервера; можно ставить считыватель где удобно; легко
подключить второй считыватель/антенну позже; считыватель не зависит от Python-кода
приложения.

## 2. Что нужно установить

| Компонент | Где | Пакет/образ |
|---|---|---|
| MQTT-брокер | сервер (Docker) или ПК в сети | `eclipse-mosquitto:2` |
| Драйвер YanPoDo + MQTT-мост | ПК/RPi у финиша | `swrfid[mqtt]` (Python 3.8+, FTDI-драйвер) |
| Подписчик в приложении | сервер | `paho-mqtt` (добавить в requirements) |

## 3. Шаг 1 — поднять брокер

Вариант A — отдельный контейнер в `docker-compose.hrono.yml`:

```yaml
  mosquitto:
    image: eclipse-mosquitto:2
    container_name: chrono-mqtt
    restart: unless-stopped
    volumes:
      - ./mosquitto/mosquitto.conf:/mosquitto/config/mosquitto.conf:ro
      - ./mosquitto/passwd:/mosquitto/config/passwd:ro
    expose:
      - "1883"
    networks: [edge]
```

`mosquitto/mosquitto.conf` (LAN, без TLS):

```
listener 1883 0.0.0.0
allow_anonymous true
persistence false
log_dest stdout
```

Если нужен пароль (рекомендую, если сеть не изолирована):

```
listener 1883 0.0.0.0
allow_anonymous false
password_file /mosquitto/config/passwd
```

`passwd` создаётся: `docker run --rm -it eclipse-mosquitto:2 mosquitto_passwd -c /mosquitto/config/passwd chrono`.

Проверка с сервера: `docker exec chrono-mqtt mosquitto_sub -t 'chrono/#' -v`
(в другом терминале публикуем тест — см. шаг 4).

Вариант B — брокер на ПК у финиша (если сервер недоступен по сети): то же самое,
только приложение подписывается на `mqtt://<ip-финишного-ПК>:1883`. Минус — сервер
должен видеть этот ПК.

## 4. Шаг 2 — настроить считыватель и мост

На ПК/RPi у финиша (Windows/Linux):

```bash
pip install "swrfid[mqtt] @ git+https://github.com/jasoisjaso/swrfid.git"

swrfid list-ports            # найти FTDI-порт (COM3 / /dev/ttyUSB0)
swrfid --port COM3 info      # проверить связь
swrfid set-region EU         # регион (для РФ — уточнить по документу считывателя)
swrfid set-power 0x1A        # мощность (0x1A = 26 dBm у RU5300)
swrfid antenna               # какие антенны подключены
swrfid inventory             # проверить чтение метки вблизи
```

Запуск моста:

```bash
swrfid-mqtt \
    --port COM3 \
    --broker mqtt://192.168.88.48:1883 \
    --topic chrono/velokros-2-etap/tags \
    --dedup 2.0 \
    --rssi-min 0x40
```

- `--topic` — **на соревнование**: `chrono/<slug>/tags` (см. шаг 3).
- `--dedup 2.0` — не повторять одну метку чаще, чем раз в 2 с.
- `--rssi-min 0x40` — отсечь слабые/дальние чтения (подобрать по месту).
- Для Home Assistant не нужно; `--ha-discovery` не включаем.

Автозапуск:
- **Linux/RPi**: systemd-юнит `swrfid-mqtt.service` (Restart=always, After=network-online.target).
- **Windows**: «Планировщик заданий» при входе или служба через NSSM.

Проверка публикации (на сервере):

```bash
mosquitto_sub -h 127.0.0.1 -t 'chrono/#' -v
# или вручную:
mosquitto_pub -h 127.0.0.1 -t chrono/test/tags \
  -m '{"epc":"3074257BF46DB64000000190","antenna":1,"rssi":70,"timestamp":"2026-11-23T10:00:00.123Z"}'
```

## 5. Шаг 3 — контракт сообщений

Топик: `chrono/<slug>/tags`, где `<slug>` — slug соревнования из `competitions.json`.

Полезная нагрузка (как публикует `swrfid-mqtt`):

```json
{
  "epc": "3074257BF46DB64000000190",
  "scheme": "sgtin-96",
  "antenna": 1,
  "rssi": 73,
  "timestamp": "2026-11-23T10:00:00.123Z",
  "reader_sn": "C3DD938E170123",
  "gtin14": "10614141123459",
  "serial": 400
}
```

Правила:
- `epc` — hex, приводим к верхнему регистру и убираем пробелы (как сейчас в
  `_process_tag_scan`);
- `timestamp` — ISO-8601 UTC, переводим в локальное naive-время сервера
  (Europe/Moscow), это время отсечки; если поля нет — берём `datetime.now()`;
- `antenna` — номер антенного порта (для будущих сплитов);
- неизвестный `<slug>` (нет в реестре, архивный/скрытый) — игнорировать и писать в лог.

## 6. Шаг 4 — подписчик в приложении

### 6.1. Настройки (БД соревнования, `settings`)

Добавить в `RFID_DEFAULTS` (`chrono/settings.py`):

```python
'rfid_mqtt_enabled': '0',
'rfid_mqtt_broker': '',            # mqtt://192.168.88.48:1883
'rfid_mqtt_topic': '',             # chrono/<slug>/tags (пусто = chrono/+/tags)
'rfid_mqtt_user': '',
'rfid_mqtt_pass': '',
'rfid_reader_sn': '',              # фильтр по серийнику (пусто = любой)
```

### 6.2. Слушатель (`chrono/rfid.py`)

Добавить рядом с `_swrfid_listener`:

```python
_mqtt_thread = None
_mqtt_stop_event = threading.Event()
_mqtt_status = {'connected': False, 'last_error': None, 'last_message': None,
                'last_epc': None, 'messages': 0}

def _mqtt_worker(queue): ...        # разбирает очередь, открывает conn на базу slug
def _mqtt_listener(): ...           # paho.Client, on_connect/on_message, reconnect
def start_mqtt_listener(): ...
```

Ключевые моменты:
- **Очередь + отдельный рабочий поток**: `on_message` только кладёт в
  `queue.Queue()`, а `_mqtt_worker` берёт сообщения и вызывает
  `_process_tag_scan(conn, epc, scan_time)` с коротким соединением
  (`_connect(_comp_db_path(entry))`) и `with conn:` — чтобы не блокировать
  сетевой поток на SQLite.
- **Роутинг по slug**: `entry = _registry_find(slug)`; если нет или `archived/hidden` —
  пропустить.
- **Фильтр по `reader_sn`**, если задан.
- **Дедуп на стороне приложения**: помнить `(epc, antenna)` за последние ~0.5 с
  (защита от двойного чтения несколькими антеннами и QoS1-дублей).
- **Статус** — обновлять `_mqtt_status` (connected, last_message, last_epc, messages)
  под `_swrfid_status_lock` или отдельным локом; страница `/auto/device` показывает.
- **Переподключение**: `client.reconnect_delay_set(min_delay=1, max_delay=30)`,
  `client.loop_forever()` в потоке, `stop_event` для остановки.
- **QoS 1** на подписке, чтобы не терять сообщения при кратком обрыве.

### 6.3. Запуск

В `chrono/server.py` → `run()` добавить вызов `start_mqtt_listener()` (рядом с
`start_swrfid_listener()`), включать только если `rfid_mqtt_enabled == '1'` или
broker задан в настройках/окружении.

### 6.4. UI

Страница «Хронометраж → RFID / авто → Устройство» (`templates/auto_device.html`):
- блок «Подключение к MQTT»: URL брокера, топик, логин/пароль, «Серийник считывателя»,
  галочка «Включено», кнопка «Сохранить» (тот же POST, что `swrfid_settings_save`);
- строка статуса: «брокер: подключён / нет», «последнее сообщение: 10:03:12»,
  «последняя метка: EPC…», «сообщений: N»;

## 7. Шаг 5 — надёжность

- **Время**: NTP на финишном ПК и сервере; иначе время круга «уплывёт». Время
  отсечки берём из `timestamp` (время считывателя), а не из момента приёма.
- **Дубли**: `--dedup` на мосте + дедуп в приложении + `min_lap_time`.
- **Порядок**: сообщения могут прийти не по порядку — в `_mqtt_worker` сортировать
  по `timestamp` в пределах короткого окна (например, 1 с) или полагаться на
  `min_lap_time`/проверку «круг не раньше предыдущего».
- **Обрыв сети**: мост переподключается, приложение — тоже; статус на странице
  устройства и в `swrfid.log`/`app.log`.
- **Резерв**: ручной хронометраж продолжает работать; MQTT — дополнение.
- **Не включать одновременно** serial-слушатель и MQTT от одного считывателя
  (двойной счёт) — либо serial, либо MQTT; в UI пометить.

## 8. Шаг 6 — тесты

- **Юнит**: парсинг payload (валидный/битый/без timestamp), роутинг по slug
  (есть/нет/архивный), фильтр `reader_sn`, дедуп.
- **Интеграция без железа**: поднять брокер, `mosquitto_pub` отправить JSON
  с EPC привязанной метки → проверить, что создан/обновлён круг, статус обновился.
- **Регресс**: ручной хронометраж, RFID через `_process_tag_scan` напрямую

- Проверка `tools/run_tests.sh` в контейнере 3.12 (paho добавить в requirements).

## 10. Этапы

1. **MVP**: брокер + `swrfid-mqtt` на финише + подписчик в приложении + статус в UI.
   Антенна игнорируется (только финиш/круг) — как сейчас.
2. **Сплиты по антеннам**: `rfid_antenna_map` (JSON: `{"1": "finish", "2": "lap"}`),
   промежуточные точки замера, расширение `_process_tag_scan`/новая
   `_process_checkpoint`.
3. **Другие считыватели**: LLRP-драйвер (б/у Impinj/Alien), Chafon/serial,
   file-replay для импорта логов.

## 11. Риски

- UHF на скорости 30–50 км/ч — пропуски чтения; ставить ворота на замедлении,
  держать ручной ввод.
- Пароль MQTT в БД в открытом виде (как и настройки swrfid) — приемлемо для
  изолированной LAN, но не публиковать брокер в интернет.
- `swrfid-mqtt` зависит от стороннего пакета — закрепить версию/коммит.

## 12. Железо подробнее

### 12.1. Считыватель YanPoDo

| Модель | Форм-фактор | Антенны | Макс. мощность | Питание | Для чего |
|---|---|---|---|---|---|
| **RU5100** | USB-настольный | 1 встроенная | 17 дБм (0x11) | USB 5 В | Программирование/проверка меток |
| **RU5300** | Корпус + внешние антенны | 1–2 порта | 26 дБм (0x1A) | USB 5 В | **Финишные ворота** (минимум) |
| **RU5500** | Модуль + мультиантенна | до 16 портов | 30 дБм (0x1E) | Обычно внешнее питание (уточнить по паспорту) | Финиш + промежуточные точки |

Общее у семейства:
- протокол **SW**, интерфейс **USB → FTDI** (VID:PID `0403:6001`), в системе
  выглядит как COM-порт / `/dev/ttyUSB*`;
- поддержка **EPC Gen2 / ISO 18000-6C** (и 6B у части моделей);
- управление мощностью, регионом, рабочим режимом (ANSWER — одиночный опрос,
  ACTIVE — поток чтения), бипер, реле;
- вендорские DLL не нужны: `swrfid` работает по документированному протоколу.

Что важно на практике:
- **Мощность** подбирается по месту (`swrfid calibrate`): больше — шире зона, но
  больше «лишних» чтений соседних меток.
- **Регион** выставить по документу считывателя (для РФ — уточнить; в ЕС 865–868 МГц).
- **Дедуп и RSSI** — на мосте (`--dedup`, `--rssi-min`), иначе одна метка даст
  десятки чтений в секунду.

### 12.2. Антенны

- **Тип**: UHF 860–960 МГц, **круговая поляризация** (важно: линейные антенны
  теряют метки, повёрнутые «не так»).
- **Усиление**: 6–9 dBi — оптимально для ворот 1–3 м.
- **Разъёмы**: SMA или N-type (проверить у считывателя; часто SMA-f).
- **Кабель**: чем короче, тем лучше. На 860 МГц RG58 теряет ~0,6–0,8 дБ/м,
  LMR-200 — ~0,35 дБ/м. При длине >3–5 м — только low-loss.
- **Монтаж**: высота 2–3 м, наклон 30–45° к потоку, антенна смотрит вдоль
  трассы; для широких ворот — две антенны навстречу.
- **Погода**: антенны под козырьком/в IP-боксе, разъёмы — в термоусадке.

### 12.3. Метки

- **Пассивные UHF Gen2 (ISO 18000-6C)**, EPC 96 бит.
- Форматы: «биб-наклейки» (Smartrac Dogbone inlay, SIVA Sprintt) — на номер;
  жёсткие метки — на раму/подседельный штырь.
- **Не клеить на металл** вплотную (рама гасит сигнал) — использовать
  «anti-metal» метки или прокладку.
- Ориентация метки относительно антенны важна; при круговой поляризации
  требование мягче.
- Запас: 10–20% меток браковать/терять; на старте проверять чтение
  (`swrfid inventory`).

### 12.4. Компьютер у финиша

- **Ноутбук** (Windows/Linux) — самый простой вариант: USB-порт, Wi-Fi/LAN,
  сразу видно `swrfid diagnose`.
- **Raspberry Pi 3/4/5** (или Zero 2 W) — дешевле и компактнее; USB-порт,
  Wi-Fi/Ethernet, systemd-автозапуск; нужен FTDI-драйвер (в Linux — из коробки).
- **Питание**: power bank/UPS на 2–4 часа; при отключении света считыватель
  и мост не должны падать.
- **Сеть**: Wi-Fi до сервера или Ethernet; при нестабильном Wi-Fi — локальный
  брокер на этом же ПК + bridge до сервера (см. п. 13.2).

### 12.5. Минимальный комплект на один финиш

| Позиция | Кол-во | Ориентир цены |
|---|---|---|
| YanPoDo RU5300 | 1 | ~$60–200 |
| Антенна UHF круговая 6–9 dBi | 1 | ~$20–50 |

## 13. Плюсы схемы «YanPoDo + MQTT» (и её ограничения)

### Плюсы

1. **Нет длинного USB-кабеля.** Считыватель и ПК стоят у трассы, сервер — где удобно
   в LAN (или в контейнере на сервере).
2. **Один сервер — несколько считывателей.** Темы `chrono/<slug>/tags` и
   `reader_sn` позволяют принимать данные с разных ворот/точек.
3. **Развязка по надёжности.** Падение/перезапуск приложения не ломает считыватель;
   мост переподключается сам, приложение — тоже.
4. **Точное время.** Время отсечки берётся из `timestamp` считывателя, а не из
   момента приёма на сервере — сетевая задержка не влияет на круг.
5. **Чистый Python без вендорских DLL.** `swrfid` (MIT) работает на Windows,
   Linux, macOS и Raspberry Pi.
6. **Дешёвое железо.** Ноутбук/RPi + YanPoDo — самый бюджетный вариант по сравнению
   с б/у Impinj/Alien и новыми R700.
7. **Диагностика «из коробки».** `swrfid diagnose`, `mosquitto_sub -t 'chrono/#'` —
   видно все отметки в реальном времени.
8. **Тестируемость без железа.** `mosquitto_pub` имитирует отметки — можно прогонять
   тесты и отладку на сервере.
9. **Расширяемость.** Тот же контракт сообщений подойдёт для LLRP (Impinj/Alien),
   Chafon и file-replay — меняется только драйвер.
10. **Безопасность/изоляция.** Брокер живёт в LAN, наружу не публикуется; можно
    включить пароль.

### Ограничения и как их снять

| Ограничение | Решение |
|---|---|
| При обрыве сети мост не доставит сообщения | Локальный брокер на финишном ПК + `bridge` до сервера; либо лог `swrfid` с последующим file-replay |
| Дубли при QoS 1 / нескольких антеннах | `--dedup` + дедуп в приложении + `min_lap_time` |
| UHF не читает на высокой скорости | Ворота на повороте/торможении, круговая антенна, ручной ввод как резерв |
| Нужна синхронизация часов | NTP на финишном ПК и сервере |
| Несколько считывателей на один номер | `reader_sn`-фильтр и тема на соревнование |
| Регуляторика по частотам | Регион в настройках считывателя по паспорту |
