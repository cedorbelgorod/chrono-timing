# Рекомендации по развитию и подбору RFID-считывателей

Статус: **исследование** (код не менялся). Составлено 23.11.2026.

## 1. Контекст: что уже есть

- Веб-приложение (Flask + SQLite на соревнование, Docker), русский интерфейс.
- Ручной хронометраж + RFID-автоотметки; массовый старт (финиш после лидера),
  разделка (круги по категориям, табло старта, «Место (сейчас)»).
- Официальный протокол PDF (ГСК, трасса, погода, подписи), публичный хаб,
  короткие ссылки `/sl/<token>`, QR, публичное табло, саморегистрация.
- RFID сейчас: пакет [`swrfid`](https://github.com/jasoisjaso/swrfid) (MIT, чистый Python) —
  считыватели **YanPoDo RU5100 / RU5300 / RU5500** (протокол SW, USB-serial/FTDI).
  Есть готовый MQTT-мост `swrfid-mqtt`.

## 3. Рекомендации по развитию (приоритеты)

### P1 — даёт больше всего при малых затратах

1. **Слой драйверов RFID.** Сейчас `chrono/rfid.py` жёстко завязан на `swrfid`.
   Ввести интерфейс `Reader` и реализации: `swrfid` (текущий), **LLRP**
   (Impinj/Alien/Zebra через [`pyllrp`](https://pypi.org/project/pyllrp/) / sllurp),
   **Chafon/serial**, **MQTT** (`swrfid-mqtt`), **file-replay** (импорт лога для тестов).
   Плюс настройка: порт/адрес, мощность, регион, антенны.
2. **Приём отметок по MQTT.** Считыватель у трассы (ноутбук/Raspberry Pi) публикует
   JSON в MQTT-брокер, сервер подписывается — не нужен длинный USB-кабель и ПК у финиша.
3. **Импорт чужих отметок** (CSV/Excel: EPC/номер + время) — чтобы принимать выгрузки
   из других систем и из «сырых» логов считывателей.
4. **Антенна/порт → точка замера.** Дать смысл антеннам: финиш, промежуточный круг,
   отсечка. Это база для сплитов.

### P2 — расширение возможностей

5. **Сплиты и лучший круг**: промежуточные точки, отсечки по кругам, лучший круг
   (как цветовые подсказки Chicha — зелёный/красный/фиолетовый на табло).
6. **Gun time vs chip time**, отсечки по времени (cutoff), политики DNF/DNS/DQ.
7. **Серии и многодневки** + общий зачёт; **награды по возрастным группам** (авто).
8. **Масштаб**: индексы, пакетные вставки, проверка на 3–5 тыс. участников,
   опция PostgreSQL (сейчас SQLite на соревнование — узкое место на больших стартах).
9. **Публичный JSON API** для табло/стримеров, автообновление хаба.

### P3 — надёжность и удобство

10. **Мастер настройки считывателя** в интерфейсе (порт, регион, мощность,
    калибровка как `swrfid calibrate`), подсказки «почему не читает».
11. **Бэкап/восстановление из UI**, офлайн-режим судьи (очередь действий при обрыве сети).
12. **Импорт заявок** из внешних платформ, экспорт в распространённые форматы.

## 4. Считыватели: что есть и что подходит для велогонок

**Ключевой момент:** дешёвые настольные USB-считыватели (1–20 см) подходят для
**программирования меток и подсказок**, но **не для финишных ворот**. Для гонок нужен
считыватель с внешними антеннами и мощностью ≥ 20–26 дБм, а лучше — с несколькими
антенными портами.

| Вариант | Модель / цена (ориентир) | Антенны | Для велогонок |
|---|---|---|---|
| **Уже используется** | YanPoDo RU5300 / RU5500 (~$60–200) | RU5300: 1–2; RU5500: до 16 | Да: RU5300 — финиш, RU5500 — финиш + промежуточные точки |
| Дешёвый USB | Chafon CF-RU5102/5102K — **10 800 ₽** ([rfid.spb.ru](https://rfid.spb.ru/schityvatel-uhf-cf-ru5102k)) | 1 встроенная | **Нет** для ворот: 13 дБм, 1–20 см — только метки/проверка |
| Бюджетный «ворота» | Royal Ray RRU9816 — **19 500 ₽** ([rfid.spb.ru](https://rfid.spb.ru/royal-ray-rru9816-usb-232)) | 1–2 внешние | Да, базовый уровень |
| Модуль для DIY | UHF-модуль для Raspberry Pi (~$25–30, AliExpress) | внешняя | Для экспериментов/малых стартов |
| Комплект «для гонок» | Athlete timing kit (Alien H3 метки) ~$200 AliExpress | 1 | Начальный уровень |
| Б/у профи | **Alien ALR-9680**, **Impinj Speedway R220** (~$300–800) | до 4 | Да: LLRP, выше темп чтения на скорости |
| Новые профи | Impinj R700, Zebra FX9600 | до 4–8 | Да, дорого |

**Метки:** пассивные UHF Gen2 (860–960 МГц), «биб-наклейки» (Smartrac Dogbone inlay,
[SIVA Sprintt](https://shenghero.co.jp/product/siva/sprintt-slim-m830/)), жёсткие метки
на раму. Ориентир цены: наклейка ~10–50 ₽ в зависимости от партии
(в розницу G9201 — 50 ₽).

**Вело-специфика (важно):**
- На финише скорость 30–50 км/ч → зона чтения должна быть 1–3 м, антенны —
  круговой поляризации, монтаж 2–3 м, под углом к потоку.
- По опыту Chicha, на скоростях выше ~25–30 км/ч UHF-чтение ненадёжно —
  **ворота лучше ставить на повороте/торможении**, а не на быстром спуске.
- Метку — на раму или номер (не в карман), с запасом от металла.
- Для нескольких точек замера нужен считыватель с несколькими антенными портами
  (RU5500 или б/у Alien/Impinj).
- Регуляторику (регион 860–868 МГц) выставлять в настройках считывателя.

## 5. Как интегрировать (минимальный путь)

1. Абстракция `Reader` в `chrono/rfid.py` + реестр драйверов (см. P1.1).
2. Для текущего железа — оставить `swrfid` как первый драйвер (работает).
3. Добавить MQTT-приём (P1.2) — это позволит использовать считыватель на любом ПК
   рядом с трассой без переделки сервера.
4. Добавить LLRP-драйвер для б/у Impinj/Alien (P2) — когда появятся такие считыватели.
5. Хранить в БД: `epc → номер` (уже есть `bib_tags`), `антенна → точка замера`,
   флаг «финиш/круг», RSSI и время чтения (уже есть `auto_laps`).

## 6. Риски и оговорки

- Цены — ориентировочные, зависят от поставщика/партии/курса.
- Дешёвые USB-считыватели с малой мощностью не заменяют финишные ворота.
- UHF на высокой скорости требует подбора антенн/места; возможны пропуски —
  оставлять ручной ввод/резервный считыватель.
- Б/у Impinj/Alien — LLRP, но нужен сетевой интерфейс и PoE; проверять комплектность.
