# Задача: тесты (tests/) и фиксация окружения

Статус: **реализовано** (23.11.2026). Тесты — `tests/`, окружение — пины и Python 3.12.

Примечания по факту:
- прогрев на локальном Python 3.15 (3.12 локально нет; авторитетный прогон — в контейнере 3.12);
- `swrfid` закреплён на коммит `7726687` (было `main.zip`);
- постоянный `CHRONO_SECRET_KEY` на сервере уже задан в `docker-compose.yml`.


## 0. Контекст

- `app.py` — 7172 строки, 118 маршрутов; тестов в репозитории нет (`tests/` отсутствует).
- Локальный venv — **Python 3.15.2**, сервер — `python:3.12-slim`.
- Зависимости не закреплены: `reportlab>=4.0`, `qrcode>=8.0`, `pyserial>=3.5`,
  `swrfid @ .../main.zip` (изменяемая ветка).
- `CHRONO_SECRET_KEY` при отсутствии генерируется временный → рестарт контейнера разлогинивает.

## 1. Тесты (`tests/`)

### 1.1. Инфраструктура

1. Добавить `tests/` с pytest и `conftest.py`.
2. Изоляция путей: тесты **не трогают** рабочие `chrono.db`/`comps/`/`log/`. Перед `import app`
   задать окружение `CHRONO_DB`, `CHRONO_REGISTRY`, `CHRONO_LOG_DIR` в временную папку
   (или фикстура, перезаписывающая модульные глобалы `app.DB_PATH`, `app.DATA_DIR`,
   `app.COMPS_DIR`, `app.BACKUP_DIR`, `app.PEOPLE_DB` после импорта и вызывающая
   `app.init_db()` + `app._ensure_registry()`).
3. Фикстуры: `client` (тестовый клиент Flask), `seeded` (соревнование с категориями,
   участниками, номерами), `itt_heat` (разделка), `mass_heat` (массовый).
4. **Сделать импорт swrfid необязательным** в `app.py`: `try: from swrfid import RFIDReader
   except ImportError: RFIDReader = None` (сейчас импорт на уровне модуля — без пакета `import app`
   падает, и тесты/CI не запустятся без устройства/пакета).
5. Точка запуска «CI-стилем»: `python -m pytest -q` из корня, в `conftest.py` не требуются
   сеть, оборудование, сервер.

### 1.2. Набор тестов (перенести уже написанные сценарии)

6. **Смоук маршрутов**: `/`, `/competitions`, `/races`, `/results`, `/protocol`,
   `/protocol.pdf`, `/manual`, `/manual?mode=start`, `/dashboard`, `/finish-screen`,
   `/summary`, `/logs`, `/users` — 200 после входа; публичные без входа.
7. **Разделка**:
   - старт с табло создаёт заезд с `laps_total = planned_laps = круги категории`;
   - `manual_action`: круг → «Круг X/N», на N-м — «ФИНИШ», статус `ok`, время;
   - DNS/пропуск создаёт DNS-заезд с кругами категории;
   - RFID (`_process_tag_scan` с фиктивным тегом, `auto_enabled=1`): N меток → финиш;
   - `maybe_finish_heat` закрывает старт после финиша всех, DNS не мешают;
   - `_build_results_detail`: «Круги» (X/N) и «Место (сейчас)» внутри категории.
8. **Массовый старт**: заезды, круги, «финиш после лидера», отставание.
9. **Стартовый протокол**: страница/PDF/Excel — колонки и значения; публичная `/sl/<token>`
   и неверный токен 404.
10. **Публичный хаб**: `/p/<slug>` (кнопки, список стартов), `/p/<slug>/results`,
    `/p/<slug>/live`, `/p/<slug>/sl/<hid>`; скрытое/архивное/неизвестное → 404;
    изоляция между соревнованиями.
11. **Страница «Ссылки»**: постоянные адреса, создание/перегенерация короткой ссылки
    (старая 404, новая 200).
12. **Экспорт**: результаты xlsx (колонки), стартовый xlsx, итоговый PDF (DejaVu, без
    разрывов слов — аудит ширин).
13. **Порядок участников**: `POST /heats/<id>/order` (валидация, автосохранение),
    `/start_at`, `/reset_order`.

### 1.3. Критерий готовности

- `python -m pytest -q` — зелёный в чистом venv Python 3.12;
- тесты детерминированы (временная БД, без реального времени в спорных местах);
- прогон не создаёт/не меняет файлы вне временной папки.

## 2. Окружение

### 2.1. Python 3.12

14. Зафиксировать `requires-python = ">=3.12,<3.13"` (например, `pyproject.toml`) и/или
    файл `.python-version` со значением `3.12`.
15. Пересоздать локальный venv на **Python 3.12** (установить/найти 3.12, `python3.12 -m venv .venv`).
16. Проверить, что сервер остаётся `python:3.12-slim` (уже так) — версии локально и в проде
    совпадают.
17. (Опционально) `.github/workflows/tests.yml` на Python 3.12 — запуск п.1 при пуше.

### 2.2. Пин зависимостей

18. Взять за источник истины рабочий серверный образ: `docker exec chrono-site pip freeze`
    → зафиксировать `Flask`, `openpyxl`, `reportlab`, `qrcode`, `pyserial` (и транзитивные
    по необходимости) точными версиями в `requirements.txt` и `requirements-docker.txt`.
19. `swrfid` закрепить на конкретный коммит: `.../archive/<sha>.zip` вместо `main.zip`.
20. Оставить разделение: `requirements.txt` (локальная разработка, включая `keyboard`/`hid`
    для RFID-устройства) и `requirements-docker.txt` (сервер без `keyboard`/`hid`).
21. **Перепроверить PDF** после смены версии reportlab (4↔5 меняет метрики текста):
    прогнать аудит ширин колонок по DejaVu (протокол ITT и стартовый протокол) — 0 проблем.

### 2.3. Секретный ключ

22. Сгенерировать постоянный `CHRONO_SECRET_KEY` и задать его:
    - в `docker-compose.hrono.yml` (в `.gitignore`, на сервере) — чтобы рестарт не разлогинивал;
    - локально — `.env` (в `.gitignore`).
23. Добавить в репозиторий `docker-compose.hrono.example.yml` / `.env.example` с плейсхолдером
    и комментарием, как сгенерировать (`python -c "import secrets; print(secrets.token_hex(32))"`).
24. Оставить временный ключ только для dev-режима; при старте без ключа — то же предупреждение.

## 3. Проверка

- Чистый venv 3.12: `pip install -r requirements.txt` → `python -m pytest -q` зелёный.
- `pip install -r requirements-docker.txt` в `python:3.12-slim` собирается без ошибок.
- Рестарт контейнера на сервере не вылогинивает (ключ постоянный).
- PDF-аудит ширин — 0 проблем после пинов.
