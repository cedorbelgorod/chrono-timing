# Задача: рефакторинг монолита (app.py → пакет chrono)

Статус: **реализовано** (23.11.2026).

Факт: app.py — 266 строк (тонкий фасад), пакет `chrono/` (14 модулей) и `chrono/views/` (10 разделов).
Отклонения от плана: маршруты регистрируются через `app.add_url_rule` (имена эндпоинтов сохранены),
views импортируют помощники напрямую из `chrono.*`; app.py держит совместимый ре-экспорт имён для тестов.
Прогон: локально (42 теста + 1 skip) и в контейнере 3.12 (43 теста OK), живой деплой проверен.

## 1. Исходные данные

- `app.py` — ~7200 строк, **118 маршрутов**, ~415 функций.
- Есть страховка: `tests/` (42 теста, прогон локально и в контейнере 3.12),
  `python -m pytest tests -q` / `tools/run_tests.sh`.
- Тесты и серверный прогон импортируют приложение как `import app` и опираются
  на модульные атрибуты (`app.DB_PATH`, `app.init_db`, `app._connect`,
  `app._ensure_registry`, `app.get_db`, `app._build_results_detail`,
  `app._process_tag_scan`, `app._start_heat`, `app._build_protocol`,
  `app._pdf_font_pair`, `app.app` и т.д.).

## 2. Цели и принципы

1. Разбить монолит на пакет `chrono/` по слоям, **не меняя поведение, адреса,
   шаблоны, схему БД и тексты интерфейса**.
2. **Инкрементально**: после каждого этапа — `python -m pytest tests -q` зелёный;
   деплой и live-проверка — после этапов с маршрутами (не после каждой правки).
3. **Совместимость импорта**: сохранить `import app` как фасад (совместимостный
   слой), чтобы тесты и серверный прогон не ломались. Внутри — новый пакет.
4. Чистые функции переносим без изменений (механический перенос + исправление
   импортов); маршруты переносим в blueprint'ы по одному разделу.
5. Не трогать: `templates/`, `static/`, схему БД, публичные URL (`/p/...`, `/sl/...`),
   формат JSON API (стартовое табло, `/manual/action` и т.п.).

## 6. Риски и как их снимаем

- **Циклические импорты** между слоями → зависимости только вниз:
  `utils ← db ← settings ← timing ← pdf/results ← routes`; где нужно — локальные
  импорты внутри функций.
- **Модульные глобалы и кэши** (settings, swrfid, registry) → остаются в одном
  модуле (`db.py`/`settings.py`), остальные импортируют оттуда.
- **Поломка импорта `app`** в тестах → фасад-слой (этап 7), тесты не трогаем.
- **Потеря поведения при переносе маршрутов** → переносить маршрут вместе с его
  помощниками, сверять ответы страниц (текст/статусы) до и после.
