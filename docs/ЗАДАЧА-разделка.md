# Задача: раздельный старт (ITT) в «Хронометраже»

Статус: **реализовано** (22.11.2026), проверено локально и на hrono.cedor.ru.

## 1. Цель

Поддержать гонку с раздельным стартом: участники стартуют по одному с интервалом,
результат — личное время (финиш минус старт).

Границы первой версии:

- **один формат на соревнование** (см. п. 2);
- старт и финиш — **в разных местах**;
- **на старте считывателя нет**: старт фиксирует стартовый хронометрист по табло;
- на финише — финишный хронометрист (кнопка; RFID на финише — если включён, метка = финиш);
- реализуется только разделка; критериум и фигурное вождение — отдельные задачи.

Не входит в первую версию: второй считыватель, ручная перестановка очереди,
два заезда, промежуточные отсечки.

## 2. Модель «формат старта»

- У соревнования появляется **формат**: `competitions.format` — `mass` (по умолчанию,
  текущее поведение) или `itt`.
- Тип **пробрасывается в старты**: `heats.format` заполняется из соревнования при создании
  старта. В первой версии настройка формата — в настройках соревнования.
- Параметры разделки (настройки соревнования, применяются ко всем стартам):
  - `itt_start_interval` — интервал старта, секунд (**настраиваемый, по умолчанию 30**);
  - порядок старта — **по возрастанию номеров** (без ручной перестановки в v1).

Миграция: `ALTER TABLE competitions/heats ADD COLUMN format TEXT NOT NULL DEFAULT 'mass'`;
существующие базы остаются в `mass` без изменений поведения.

## 3. Стартовое табло (внутри «Хронометража»)

Страница «Хронометраж» получает **два режима**: «Финиш» (текущий) и «Старт» (табло).
Переключатель в шапке + прямая ссылка `/manual?mode=start` (для телефона стартового судьи
и для Android-приложения — см. п. 7).

Состав табло:

1. **часы** (крупно) и название старта;
2. **следующий участник**: «Стартует: №12 — ФИО», категория;
3. **отсчёт до планового старта** (минус-секунды до расчётного времени), крупно;
4. очередь вперёд: следующие 5 участников;
5. **кнопка «СТАРТ»** — фиксирует фактический `start_time` текущему участнику;
6. кнопки **«Пропустить»** (DNS, участник не явился) и **«↶»** (отменить последний старт);
7. лента последних стартов: №, ФИО, время старта (последние ~8);
8. звуковой отсчёт: сигнал на 5-4-3-2-1 и «старт» (настраивается, вкл/выкл);
9. автообновление 2 с (как сейчас) — чтобы видеть финиши с другой точки.

Логика планирования: расчётное время следующего старта = **фактический последний старт +
интервал**. Первый старт — по нажатию (или по кнопке «Начать старт», которая фиксирует
старт первому участнику). Если судья нажал раньше/позже — источник истины фактическое время,
следующий план пересчитывается от него. Задержался/не явился — «Пропустить» (участник
получает DNS, очередь идёт дальше). Ошибочный старт — «↶» снимает последний.

## 4. Финиш

Текущая страница «Хронометраж» в режиме «Финиш»:

- у разделки `laps_total = 1`: кнопка участника — сразу «ФИНИШ»;
- у едущих показывается **живое время** (сейчас − его старт);
- **RFID на финише**: считанная метка = финиш; ручная кнопка остаётся как основной/запасной способ;
- защита: нельзя финишировать, если нет старта; нельзя стартовать дважды.

Завершение старта: когда все в стартовом протоколе имеют статус «финишировал» или DNS
(или принудительно, как сейчас).

## 5. Результаты, табло, протокол

- **Ранжирование** для `itt`: по времени результата (финиш − старт), меньше — лучше;
  DNS/DNF — после всех, отдельной строкой. Место и отставание — от первого.
- **«Что сейчас идёт»**: Стартовали / Едут / Финишировали; у едущих — живое время.
- **Экран финиша** (публичный): финишёры с результатами.
- **Протокол**: №, ФИО, категория, время старта, время финиша, результат, место, отставание.
  PDF — тот же механизм, другой макет таблицы.
- **Экспорт** результатов — с колонками старт/финиш/результат.

## 6. Права и роли

В первой версии оба судьи (стартовый и финишный) — любые пользователи с доступом
к хронометражу (хронометрист/судья/админ); разделение по ролям («судья старта»,
«судья финиша») — опционально, позже.

## 7. Android-приложение

Приложение открывает `/manual`; для стартового судьи нужен вход в режим табло —
разрешить `/manual?mode=start` (проверить allowlist) и помнить последний режим.

## 8. Порядок работ

1. **Данные:** колонки `format` в competitions/heats, настройки `itt_*`, миграция,
   установка формата в настройках соревнования.
2. **Каркас режимов:** `/manual?mode=start`, переключатель, передача формата на страницы
   (без новой логики; `mass` ведёт себя как раньше).
3. **Табло старта:** очередь, план/интервал, «СТАРТ», «Пропустить», «↶», лента, звук.
4. **Финиш для itt:** laps=1, живое время, запрет финиша без старта.
5. **Результаты/дашборд/протокол/экспорт** под itt.
6. **Тесты:** сквозной сценарий (10 участников, интервал 20 с, пропуск одного, отмена
   ошибочного старта, финиши с двух устройств), проверка мест и протокола.
7. **Деплой и проверка на hrono.cedor.ru.**

## 10. Что сделано

- `competitions.format`, `heats.format`, настройки `itt_start_interval`, `itt_countdown_sound`,
  миграция существующих баз в `mass`.
- Страница «Соревнование» → «Формат стартов» (тип, интервал, звук).
- Табло старта `/manual?mode=start`: очередь по номерам, план = последний старт + интервал,
  СТАРТ / Пропустить (DNS) / ↶, лента стартов, звук 5-4-3-2-1, автообновление 2 с.
- API `/manual/start/data` и `/manual/start/action`.
- Разделка в «Хронометраже»: заезды создаются в момент старта, у едущих «в пути», финиш
  по кнопке или метке, лишний финиш без старта невозможен.
- Старт не закрывается, пока есть не стартовавшие (проверка в `maybe_finish_heat`).
- Результаты: таблица «Место / Старт / Финиш / Время / Отставание», экспорт Excel с теми же колонками.
- Протокол и PDF: колонки «Старт» и «Финиш» для разделки.
- Попутно: старты без меток и без номеров работают как раньше (регресс проверен).
- **Ручная перестановка очереди** (добавлено сверх плана): `heat_participants.sort_order`,
  стрелки ↑ ↓ на табло, порядок сохраняется; табло показывает и ещё не запущенный старт
  (режим предпросмотра) с кнопкой «▶ Начать старт».

Не вошло в эту версию (как и договаривались): второй считыватель,
два заезда, промежуточные отсечки, отдельные роли «судья старта/финиша».

## 11. Принятые решения

1. **Интервал старта** — настраиваемый в настройках соревнования, по умолчанию 30 с.
2. **Порядок старта** — по возрастанию номеров; ручной перестановки в v1 нет.
3. **Финиш** — кнопка + RFID на финише (метка = финиш); кнопка остаётся запасным способом.
4. **Звук** — отсчёт 5-4-3-2-1 и сигнал «старт», отключаемый.
5. **Пропуск опоздавших** — кнопка «Пропустить» → DNS, очередь идёт дальше.
6. **Аккаунты** — один аккаунт, режим выбирается переключателем «Старт/Финиш»
   (и прямой ссылкой `/manual?mode=start`).

Задача готова к реализации. Начать можно с этапа 1 (данные) и этапа 2 (каркас режимов).
