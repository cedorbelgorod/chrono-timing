# Задача: страница «Соревнование» — дашборд подготовки

Статус: **реализовано** (23.11.2026).

Уточнения: «протокол заполнен» считается по непустому `proto_title`;
название и формат — две отдельные карточки сверху, как и было.

## 1. Решения

1. Страница `/competitions` — **дашборд/обзор** подготовки, а не простыня настроек.
2. «Данные для протокола» (форма ~16 полей) переносим **на страницу «Протокол»** (`/protocol`).
3. Добавляем **чеклист прогресса подготовки** с явными статусами.
4. Блок «Новое соревнование — новая база» **удаляем**, заменяем ссылкой
   «Новое соревнование → Управление соревнованиями» (`/manage`).

## 2. Целевая структура `/competitions`

Сверху вниз:

1. **Основное** — название (inline-правка) и формат стартов (масс/разделка +
   интервал ITT, звук) одной компактной формой.
2. **Готовность к старту** — чеклист этапов, каждый со счётчиком, статусом
   «готово / не готово» и переходом:
   - Категории (N)
   - Участники (N)
   - Номера выданы (N из M)
   - RFID-метки привязаны (N из M)
   - Старты (N)
   - Протокол — «данные заполнены / не заполнены» (переход на `/protocol`)
3. **Быстрые действия** — кнопки: «Добавить участников», «Импорт из Excel»,
   «Выдать номера», «Привязать метки», «Создать старт».
4. Ссылка «Данные протокола →» (на `/protocol`).
